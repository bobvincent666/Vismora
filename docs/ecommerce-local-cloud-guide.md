# 电商模特换装教程：本地 ComfyUI 与云端图像 API

适用项目：`ai-pose-gallery-zh` 的本地增强版。整理日期：2026-11-01。

本教程以当前已经下载、配置并修改的项目为依据。2026 年 11 月 8 日已将上游基线从 `19ea0e5` 同步至 `4889391`，`package.json` 版本为 `2.0.0`；本次扩展属于保留的本地改动，并不代表重新下载上游仓库就能获得这些功能。新版还支持深度参考图、工作流高级参数、任务进度跟踪与刷新恢复。

文中示例根目录统一使用 `D:\AI`。请替换成自己的目录，不需要移动已经安装的项目。教程不附带模型、参考照片或 API Key。

## 1. 电商应用场景与能力边界

本项目可以把人像、商品服装和姿势参考组合起来，辅助制作电商视觉素材。

| 应用场景 | 输入素材 | 预期用途 |
| --- | --- | --- |
| 固定模特换装 | 人像、服装、姿势 | 同一模特展示不同商品 |
| 同款多姿势展示 | 固定人像和服装，更换姿势 | 制作站立、侧身、抬手等不同展示构图 |
| 商品展示风格统一 | 相近光线、背景与构图要求 | 制作视觉风格一致的商品图初稿 |
| 多人服装展示扩展 | 两个人像、多人姿势、可选女士服装 | 两个独立人物在同一画面中展示 |

“自动换装”指生成新的展示图，不是模拟真实试穿。模型不能据此判断尺码是否合适，也不能保证面料物理表现、版型、商标、印花和人物身份完全一致。正式使用前，应核对颜色、领口、袖型、扣件、图案、配饰、手脚结构及画面完整性。

姿势图是参考，不是当前工作流中的硬性骨骼约束。Turbo 模型加姿势 LoRA 仍可能忽略头部角度、改变手势或错误处理遮挡。增加采样步数、提高 LoRA 强度都不能直接保证解决这些问题。

优先使用自己的商品图片与已授权的模特素材；项目内的图库不应被理解为附赠了全部素材的商用授权。

## 3. 下载与启动网页项目

### 3.1 先保留当前增强版

当前文件夹包含尚未发布到上游的新增文件。重新克隆上游仓库，只能取得上游版本，不能替代本机增强版备份。

当前电脑已经下载项目，可以直接进入下一节。新电脑若只需获取上游基础代码，可执行下列命令；它不包含本教程列出的全部本地扩展：

```powershell
Set-Location -LiteralPath 'D:\AI'
git clone https://github.com/anhao/ai-pose-gallery-zh.git
```

需要复现本教程的增强功能时，应复制当前增强版源码，或使用另行保存的增强版代码包。本教程下载包只包含教程和5份工作流，不包含完整项目、模型或图库。

首次复制到另一台电脑时，保留当前项目源码、锁文件、`data`、`img`、`thumbs` 和教程工作流；`node_modules` 与 `dist` 可以在目标电脑重新生成。不要覆盖原文件夹后再尝试找回本地改动。

### 3.2 检查环境并安装依赖

打开 PowerShell：

```powershell
$projectRoot = 'D:\AI\ai-pose-gallery-zh'
Set-Location -LiteralPath $projectRoot

node --version
corepack pnpm --version
corepack pnpm install
```

若提示找不到 `node` 或 `corepack`，先配置 Node 环境并重新打开终端。本机目前这两项已可直接使用，无须重复安装。

### 3.3 启动网页并连接当前 ComfyUI 端口

```powershell
Set-Location -LiteralPath 'D:\AI\ai-pose-gallery-zh'
$env:COMFYUI_URL = 'http://127.0.0.1:8188'
corepack pnpm dev --host 127.0.0.1 --port 5173 --strictPort
```

打开 <http://127.0.0.1:5173/studio>。启动终端要保持运行；关闭终端会停止网页开发服务。

`COMFYUI_URL` 在 Vite 启动时读取。未设置时，项目代理默认指向 `8000`，与本机便携版的 `8188` 不同。修改端口后需要重启网页服务。

`--strictPort` 可以防止端口被占用后静默切到其他端口。遇到端口占用，先确认原网页服务是否仍在运行；不要随意终止不明进程。

### 3.4 日常启动顺序

1. 启动 ComfyUI，确认 `8188` 页面可打开。
2. 用上面的 PowerShell 命令启动网页。
3. 打开合成台，检查当前服务商与工作流。
4. 选择参考图，先做一张小批量验证，再开展商品图制作。

只使用云端时，可以跳过第一步，但网页服务仍需运行。

## 4. 本地 ComfyUI 配置

### 4.1 启动与检查服务

本机使用便携版，可从文件资源管理器运行 `run_nvidia_gpu.bat`。或者在 PowerShell 中执行：

```powershell
Set-Location -LiteralPath 'D:\AI\ComfyUI_windows_portable'
.\run_nvidia_gpu.bat
```

等待服务启动后访问 <http://127.0.0.1:8188>，也可以做只读检查：

```powershell
$stats = Invoke-RestMethod 'http://127.0.0.1:8188/system_stats'
$stats.system.comfyui_version
```

### 4.2 复用已存在的模型

本教程配套的自定义工作流复用以下模型；文件名应与工作流一致。

| 用途 | 文件名 | 所在目录 |
| --- | --- | --- |
| Turbo 主模型 | `Qwen-Image-2.1-Turbo-AD-Q4_K.gguf` | `ComfyUI/models/unet/` 或该加载器已配置的模型目录 |
| 图文编码器 | `Qwen-Image-2.1-Turbo-Uncensored-AD-Q4_K.gguf` | `ComfyUI/models/clip/`、`models/text_encoders/` 或已配置目录 |
| VAE | `qwen_image_2.1_vae_bf16.safetensors` | `ComfyUI/models/vae/` |
| 姿势 LoRA | `VNCCS_QI2_PoseStudioV1.1.safetensors` | `ComfyUI/models/loras/` |

目录以本机加载器能实际列出该文件为准。文件在下拉框中已可选，就不必为配合示例路径再复制一份大模型。

注意区分项目内置的 Qwen Image Edit 2509 预设和本教程的 Turbo 自定义工作流。两者模型、编码节点与采样设置不同。选择内置预设不会自动替换成当前已有的 GGUF 模型。

### 4.3 所需节点

| 节点 | 本机状态及作用 |
| --- | --- |
| `UnetLoaderGGUF`、`CLIPLoaderGGUF` | 已安装，用于加载本机 GGUF 模型与编码器 |
| `TextEncodeQwenImage21` | 已可用，接收多张参考图及正反向提示词 |
| `LoraLoaderModelOnly` | 已可用，将姿势 LoRA 接入模型链路 |
| `ManualSigmas`、`SamplerCustom`、`KSamplerSelect` | 已可用，使用当前 Turbo 采样流程 |
| `LoadImage`、`VAELoader`、`VAEDecode`、`SaveImage` | 已可用，负责输入、解码与保存 |

本机存在 `ComfyUI-GGUF` 与 `ComfyUI-Easy-Use` 自定义节点目录；不要将目录名直接等同于所有节点的来源。换电脑时，以导入后缺失节点提示及项目的“检查工作流”结果为准。需要安装依赖时，使用 `python_embeded/python.exe -m pip`，避免装到系统 Python。

将节点文件或模型补齐后重启 ComfyUI，再执行检查。不要看到缺失节点就无差别更新整套环境。

### 4.4 保留当前 Turbo 参数

| 参数 | 配套工作流值 |
| --- | --- |
| 姿势 LoRA 强度 | `1.0` |
| 采样器 | `euler` |
| CFG | `1` |
| 编码参考分辨率 | `768` |
| 默认种子 | `24092026` |

## 5. 工作流选择与导入

### 5.1 先分清两种 JSON

| 格式 | 主要特征 | 用途 |
| --- | --- | --- |
| 画布格式 | 顶层通常有 `nodes`、`links` | 在 ComfyUI 里查看、连接和调参 |
| API 格式 | 顶层以节点 ID 为键，每个节点有 `class_type`、`inputs` | 导入网页合成台并提交给 ComfyUI |

文件名是否带 `.api` 不是判断依据。由 ComfyUI 导出的文件，即使名称只是 `.json`，内容也可能已是 API 格式。网页发现画布格式时会提示重新导出 API。

### 5.2 本教程配套文件

| 文件 | 用途 | 输入 |
| --- | --- | --- |
| [单人三图画布版](ecommerce-workflows/single-person-3img.json) | 在 ComfyUI 中调试 | 姿势、人像、服装 |
| [单人三图 API 版](ecommerce-workflows/single-person-3img.api.json) | 网页电商换装 | 姿势、人像、服装 |
| [双人物画布版](ecommerce-workflows/two-person-2portraits.json) | 多人展示的身份输入基础 | 姿势、人物A、人物B；服装由文本指定 |
| [双人物 API 版](ecommerce-workflows/two-person-2portraits.api.json) | 网页多人展示基础 | 姿势、人物A、人物B |
| [可选女士服装 API 版](ecommerce-workflows/two-person-optional-womens-clothing.api.json) | 网页多人展示与女士换装 | 前三张必需，第4张女士服装可选 |

最后一份工作流的“服装可选”由增强版网页在提交前实现。直接把原始 API 文件交给 ComfyUI 时，没有网页执行空节点移除与提示词处理，不能据此期待同样的可选行为。纯画布操作时，应明确连接服装图，或手动断开第4图并相应修改提示词。

### 5.3 网页导入步骤

1. 在合成台选择“本地 ComfyUI”。
2. 将连接地址设为 `/comfy`；本地没有鉴权时 Key 留空。
3. 在工作流配置中导入相应的 API 文件。
4. 检查人像、人物B、服装、姿势与拼图的节点映射。
5. 执行服务／工作流检查，处理缺失模型或节点提示。
6. 确认参考图已选择，再点击生成。

导入自定义工作流默认保留文件内提示词及固定种子。网页会显示工作流提示词，直接编辑时会启用对应的提示词节点。只导入一次旧文件后替换磁盘文件，不会自动更新浏览器里已保存的工作流；需重新导入。

### 5.4 配套工作流节点速查

| 网页槽位 | 单人三图 | 双人物基础 | 可选女士服装 |
| --- | --- | --- | --- |
| 人像／人物A | `12` | `12` | `12` |
| 人物B | 不绑定 | `13` | `13` |
| 服装 | `13`，必需 | 不绑定 | `15`，可选、仅人物A |
| 姿势 | `11` | `11` | `11` |
| 拼图 | 不绑定 | 不绑定 | 不绑定 |
| 正向提示词 | `4`，或保留文件原提示词 | 同左 | 同左 |

这些 ID 只适用于本教程配套文件。其他工作流即使看起来相似，也应重新识别节点。

## 6. 电商模特三图换装

### 6.1 准备三张图

| 参考图 | 建议素材 | 检查重点 |
| --- | --- | --- |
| 人像 | 清晰成年模特头像或上半身图 | 脸部无遮挡、发型可辨认 |
| 服装 | 商品平铺图、假模图或清楚的服装展示图 | 不同商品不要混在一张复杂拼图里 |
| 姿势 | 与目标展示接近的全身姿势图 | 四肢完整，尽量减少严重遮挡 |

优先从简单站姿和普通商品服装开始。姿势参考只有上半身、却要求全身出图时，腿部姿势属于模型补全，不能认为参考图已确定了全身动作。

### 6.2 完成一次换装

1. 导入单人三图 API 版。
2. 在“参考图组合”中选人像、服装、姿势；人物B保持空。
3. 确认节点映射为人像 `12`、服装 `13`、姿势 `11`。
4. 初次使用保留文件内提示词，关闭随机种子，便于对比。
5. 点击生成，观察检查、上传、排队、执行和结果获取提示。
6. 对照商品图逐项检查，确认后下载结果。

网页显示槽位顺序通常是人像、人物B、服装、姿势；本配套单人工作流送入模型的顺序是：**图1姿势、图2人像、图3服装**。网页通过节点映射完成转换，不是依照卡片从左到右直接编号。

### 6.3 服装未生效时先查什么

先确认服装槽绑定到 `13`，再确认最终图3来自服装节点。检查提示词是否仍有“穿白衬衫”“穿牛仔裤”等默认指令。商品图已上传，不代表模型会自动忽略冲突文本。

做对照实验时，一次只改一项：先固定人物、姿势、种子与采样参数，只替换服装；不要同时改变风格、LoRA、尺寸和提示词，否则很难判断问题来源。

## 7. 可选女士服装与多人展示扩展

本章只说明新增输入和服装规则，不展开独立的双人互动姿势教程。

### 7.1 输入角色

导入“可选女士服装 API 版”后，模型接收：

| 模型图片编号 | 内容 | 作用 |
| --- | --- | --- |
| 图1 | 多人姿势 | 两个人物的位置与姿态 |
| 图2 | 左侧人物A | 左侧女士的身份、五官与发型 |
| 图3 | 右侧人物B | 右侧男士的身份、五官与发型 |
| 图4 | 女士服装，可不选 | 只改变左侧女士的穿着 |

人物B支持独立上传、预览、更换和清除，并随配方保存在当前浏览器。没有人物B参考图时，已绑定的人物B工作流会提示缺图，不会静默沿用 ComfyUI 里的旧头像。

### 7.2 没有女士服装图

保持女士服装槽为空，仍然可以生成。网页提交前会：

1. 移除可选服装加载节点及编码器的第4图连接。
2. 为左侧女士设置默认米色长袖衬衫、牛仔裤、白鞋。
3. 为右侧男士保留深蓝衬衫、深灰长裤、黑鞋。

这是当前增强版的默认文本设定，不是从人物头像自动推断出的服装。

### 7.3 已选择女士服装图

网页会上传服装到节点 `15`，作为第4张参考图，并移除本项目旧版写入的默认女士服装要求。提示词只保留“按图4为女士换装”的要求，男士服装保持文本指定。

不要在自定义提示词里同时写“女士严格穿上传的商品”和“女士必须穿默认衬衫牛仔裤”。自动清理覆盖的是本项目已知的旧默认语句，不是能理解并清除任意中英文冲突的通用工具。

当前新增的服装槽是“左侧女士服装”，不是男女共用服装槽。若需要男士也独立参考商品服装，需要继续增加输入及对应工作流，不能把同一服装节点同时绑定两个人。

## 8. 云端图像 API 配置

### 8.1 先选协议，再填参数

云端图生图不使用本地 ComfyUI JSON，也不会读取本地模型或姿势 LoRA。云端与本地是两条独立的生成路线。

| 类型 | 典型流程 | 本项目处理 |
| --- | --- | --- |
| 同步编辑接口 | 提交参考图，响应直接带图片数据或 URL | 使用编辑接口的 JSON 或 Multipart 模式 |
| 同步聊天兼容接口 | 按服务定义提交图片消息，解析生成结果 | 使用聊天兼容模式；是否支持生图由服务定义决定 |
| 异步任务接口 | 上传图片 → 提交任务 → 查询状态 → 取图片 | 使用本次新增的“异步生图（官方渠道）”模式 |

模型名相同，不代表各服务的端点、参数和返回格式相同。某服务的 `/images/edits` 不支持目标模型时，不能靠更换提示词解决。

### 8.2 配置当前已实现的异步通道

为保持教程中性，本文只按功能名称描述模式，不介绍服务商、推荐链接或价格。当前界面的完整模式名称可能带来源前缀，识别其中“异步生图（官方渠道）”即可。

1. 在接口配置页选择“OpenAI GPT Image”。
2. 填入该图像接口账号对应的 Key。不同来源的 Key 不能混用。
3. 返回合成台，展开高级参数，选择“异步生图（官方渠道）”。
4. 选择该模式会自动填写当前适配器支持的 Base URL、`gpt-image-2-official` 模型，并打开请求代理。检查自动填写结果，不要手动拼接重复的 `/v1`。
5. 设置比例 `2:3`、分辨率 `2k`、质量 `high`、输出格式 `png`。
6. 选择自己的参考图，使用本章下文对应的云端提示词编号。
7. 提交一次后等待任务状态，不要因等待时间较长连续点击生成。

这里的“官方渠道”是当前网关的通道名称，不表示项目正在直连模型原厂地址。当前异步适配器只接受已经实现并校验的固定来源，**不是任意 Base URL 都能使用的通用异步适配器**。换另一家接口时，需要核对上传、提交和任务查询协议，再做适配。

### 8.3 上传与异步任务流程

```text
本地参考图
  → POST /v1/uploads/images（Multipart，file字段）
  → 返回可访问的图片URL
  → POST /v1/images/generations（image_urls数组）
  → 读取 data[0].task_id
  → GET /v1/tasks/{task_id}
  → completed 后读取 data.result.images[0].url[0]
```

当前实现按顺序上传，不将本地 `localhost` 图片地址直接交给云端。此模式需要1～16张参考图，上传图片类型为 PNG、JPEG 或 WebP，单张不超过20MB；网页通常已将上传图片转换或缩放。

生成请求固定 `n: 1`。每隔约4秒查询一次，轮询阶段最长等待10分钟，单次网络请求另有超时。上传、网络耗时也会占用时间，因此10分钟不是整个操作的绝对总耗时上限。

任务失败、查询断网或等待超时时会显示任务 ID。查询失败不等于任务已经取消；应先到接口任务记录中查找该 ID，避免重复提交。

### 8.4 代理与网络

网页的“请求代理”解决浏览器跨域问题；它不等于网络代理软件。开发服务还需要能够访问模型接口。

如果本机网络要求通过已运行的代理访问上游，可在启动网页的同一 PowerShell 中设置：

```powershell
# 下面端口仅为当前本机代理示例，其他电脑应填写实际监听端口。
$env:HTTP_PROXY = 'http://127.0.0.1:7890'
$env:HTTPS_PROXY = 'http://127.0.0.1:7890'
$env:COMFYUI_URL = 'http://127.0.0.1:8188'

Set-Location -LiteralPath 'D:\AI\ai-pose-gallery-zh'
corepack pnpm dev --host 127.0.0.1 --port 5173 --strictPort
```

当前 Node `24.15.0` 环境支持代码读取这些代理变量。其他旧版 Node 不应默认认为具有相同行为。无需代理时不必设置不存在的代理地址。

配置云端接口不需要把 Key 写进终端命令、工作流 JSON 或 Git 仓库。当前项目将网页接口配置保存在该浏览器的本地存储中。

### 8.5 云端验证状态

本次已验证无密钥请求能经过本地代理到达上游，以及三图上传、异步提交、轮询、结果解析和错误分支的模拟测试。实际账号曾返回内容审核拒绝；**不能据此宣称云端三图生成已经实测成功**。

首次验证建议使用自己的普通商品服装与清楚的人像、简单姿势。若返回审核拒绝，应检查提示词和输入文件；不要将它归类为网络错误，也不要连续重复相同请求。是否产生审核输入费用，以该次接口响应及账号账单为准。

### 8.6 云端运行与部署范围

本机使用云端 API：保持 Vite 开发服务运行即可，不需要本地 ComfyUI。若使用预览方式：

```powershell
corepack pnpm build
corepack pnpm preview --host 127.0.0.1 --port 5173 --strictPort
```

单独把 `dist` 放到普通静态服务器，并不自动提供 `/api/proxy`。项目中的生产函数实现需要受支持的函数运行环境；换成其他托管环境时也要部署等价代理。公网部署未在本次流程中完成端到端验证。

本地开发代理用于本机运行，不应直接当作公网开放代理服务。API Key 与参考图都会在调用时传给所选图像接口，浏览器“本地保存”不代表生成过程没有上传素材。

## 9. 电商提示词模板

### 9.1 单人三图：本教程本地工作流

这份模板的图序是姿势、人像、服装，适用于第5章的单人三图 API 文件。网页提示词节点应为 `4`。

```text
生成一张成年模特的写实全身商品展示照片。
图1只提供目标姿势、头部朝向、四肢位置和拍摄视角。
图2只提供人物身份、五官、发型和肤色。将人物自然调整到图1的姿势，不沿用图2的原有姿势和构图。
图3提供完整商品服装、鞋履和配饰。保留款式、颜色、材质、图案、领口、袖型、扣件与搭配，不复制服装图中其他人物的身份和姿势。
以图1可见的姿势为准，不额外夸大动作。完整保留头顶和鞋子，双手按参考姿势自然呈现。
使用中性棚拍光线与简洁背景，衣物纹理清楚，人体结构自然。
不复制人偶表面、关节圆圈和辅助线，不生成文字、水印或拼图。
```

### 9.2 云端三图：编号不同

云端当前按“人像 → 人物B（如有）→ 服装 → 姿势 → 附图”发送实际存在的图片。没有人物B时，单人三图是图1人像、图2服装、图3姿势。

```text
生成一张成年模特的写实全身商品展示照片。
图1提供人物身份、五官、发型和肤色。
图2提供商品服装、鞋履及配饰，保持款式、颜色、图案和材质。
图3提供目标姿势、头部朝向和拍摄视角，不复制人偶外观或辅助线。
让图1的人物穿着图2的服装，采用图3的姿势。
完整显示人物与鞋履，使用中性棚拍光线和干净背景，不生成文字、水印或拼图。
```

不要将本地工作流的图序模板直接用于云端。缺少一个槽位时，后面的云端图片编号也会随之变化。

### 9.3 可选女士服装模板原则

配套可选服装工作流已有身份和姿势提示词，优先保留，再按商品展示需求修改光线与背景。

| 状态 | 应出现的服装要求 |
| --- | --- |
| 有服装图 | 图4是左侧女士的服装参考，保留商品细节；不再指定默认女装 |
| 无服装图 | 使用默认女士服装；不要求模型读取不存在的图4 |

若需要固定背景，可追加：“浅灰无缝摄影背景，柔和侧前方主光，地面有自然接触阴影。”服装适配、姿势和背景一次不要同时做过多复杂改动。

## 10. 常见问题与排查

| 现象 | 优先检查 | 处理 |
| --- | --- | --- |
| 网页打不开 | 5173服务是否运行 | 回到启动终端查看错误，使用固定端口启动 |
| ComfyUI 无法连接 | 8188是否在线，代理是否仍指向8000 | 设置 `COMFYUI_URL` 后重启网页，连接填 `/comfy` |
| `[GPT] fetch failed` | Vite到上游的网络路径 | 检查代理软件、终端环境变量与 Node 版本；与浏览器跨域分开排查 |
| 编辑端点仅支持其他模型 | 当前接口模式与服务协议不符 | 按服务实际支持的同步或异步协议配置 |
| 内容审核拒绝 | 提示词、输入图片及服务响应 | 不视为“上传成功就能生成”；先检查内容及已有任务记录 |
| 缺少必填 `images` | 是否仍使用未修复的旧代码 | 使用增强版动态输入校验；核对展开字段 `images.image_1` 等 |
| 工作流模型不存在 | 是否误用内置2509预设或不同模型文件名 | 导入本教程的 Turbo 自定义工作流，检查本机加载器列表 |
| 提示缺少服装，但工作流没有服装 | 服装槽是否误绑定人物B节点 | 重新导入正确 API，人物B为13，服装应不绑定或为可选15 |
| 同一头像覆盖另一个人物 | 两个角色是否绑定同一节点 | 分别绑定人物A12、人物B13，重复映射会被拦截 |
| 服装上传了仍生成衬衫牛仔裤 | 最终提示词是否有默认服装冲突 | 使用修正版可选服装工作流，刷新页面并重新导入 |
| 不能输入或提示词没生效 | 是否是旧页面或保留文件提示词模式 | 刷新增强版页面；直接编辑后检查正向节点4 |
| 姿势只部分跟随 | 参考姿势难度、遮挡、身份与姿势竞争 | 先固定种子做简单姿势对照，不直接认定为传图错误 |
| 显存不足 | 模型、分辨率、占用和输入图数量 | 关闭无关显卡任务，降低参考分辨率试验；不要套用其他工作流的节点参数 |
| 等待超时 | 本地排队或云端任务是否仍在执行 | 本地查看ComfyUI队列；云端按任务ID查询，不立即重复提交 |

ComfyUI 等待超时或停止跟踪后，后台任务仍可能继续执行，可恢复查看；刷新页面会尝试恢复已记录的任务。云端查询超时同样不代表远端任务已取消。应先确认任务状态，再决定是否重新提交。

## 11. 备份与迁移

### 11.1 需要保留什么

| 对象 | 建议保存方式 |
| --- | --- |
| 增强版网页源码 | 复制完整项目，包含新增模块与测试；不能只保留上游仓库地址 |
| 工作流 | 保存画布 JSON、API JSON及对应节点映射说明 |
| 模型与LoRA | 记录文件名和目录，按需要复制模型文件 |
| 自定义节点 | 记录目录和版本，新环境重新核对依赖 |
| 输入商品及人像 | 单独保存原始素材，不把浏览器缓存作为唯一副本 |
| 生成结果 | 下载原图；保留需要的 `ComfyUI/output` 文件 |
| 云端Key | 通过可信的凭据管理方式保存，在新浏览器重新配置 |

当前浏览器数据包括：

| 存储 | 内容 |
| --- | --- |
| `localStorage`：`pose_atlas_api_config_v3` | API配置、Key、工作流及节点映射 |
| `localStorage`：配方轻量备份 | 图库选择等；不保存上传参考图正文 |
| IndexedDB：`pose_atlas_studio_db` / `kv_store` | 上传图片、人物B、完整配方与历史记录 |

配置导出或浏览器存储备份可能含真实 Key，应与公开教程、代码包分开保存。不要把整份浏览器配置贴进工单或提交到 Git。

### 11.2 迁移顺序

1. 在新电脑准备 Node 与包管理器，复制增强版项目并安装依赖。
2. 若走本地路线，准备 ComfyUI、模型和节点，确认其端口。
3. 按新目录设置启动命令，保持网页使用相同的主机名和端口。
4. 在新浏览器重新配置连接、导入工作流、上传原始素材。
5. 固定种子生成一张验证图，再进行后续制作。

`localhost` 与 `127.0.0.1`、不同端口属于不同的浏览器来源，不能假定它们共享已保存的 Key、工作流和历史记录。清理站点数据或使用隐私窗口，也可能使原有配置不可见。

云端结果可能只是有有效期的 URL。当前历史记录保存 URL，不等于已经永久下载了云端图片；重要结果应及时下载到文件夹。

## 附录C：工作流文件与模型的关系

配套 JSON 只保存模型文件名、节点连接和参数，不包含模型权重。导入 JSON 后出现模型缺失，需要安装或重新选择对应模型，而不是再次下载同一 JSON。

`pose.json`、`pose-zh.json` 等图库数据描述的是姿势条目、图片和检索信息；它们不是采样器，也不是姿势控制模型。编辑图库名称不会提高模型的动作还原能力。
